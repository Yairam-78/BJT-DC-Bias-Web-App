# Reflection — Lab 02 BJT DC Bias Web App

## 1. เหตุใดการเปิด `templates/index.html` ตรง ๆ จึงไม่เท่ากับการรัน Flask

ไฟล์ `templates/index.html` ไม่ใช่หน้าเว็บสำเร็จรูป แต่เป็น **Jinja template**
ที่ยังมีโค้ดของ templating ค้างอยู่ เช่น `{{ "%.3f"|format(result.vb) }}`
และ `{% if result %}` ซึ่งเบราว์เซอร์ไม่รู้จัก

ถ้าเปิดด้วย `file://` จะเกิดสามปัญหา

1. ตัวแปรทั้งหมดยังว่าง — หน้าจะแสดงโค้ด `{{ ... }}` ดิบ ๆ หรือกล่องผลลัพธ์ว่าง
2. ไม่มีใครรับ `POST` ที่ action `/calculate` — ไม่มี HTTP server ทำงาน
3. ไม่มี Python คำนวณ — ต่อให้กรอกค่าแล้วกดปุ่ม ก็ไม่มีอะไรเกิดขึ้น

การรัน Flask (`python -m flask --app app run`) จะสร้าง **HTTP server** ขึ้นมาจริง
เมื่อเบราว์เซอร์ขอ `GET /` ตัว Flask จะเอา template ไป render ด้วยข้อมูลจริง
(เติมค่าเริ่มต้นลงในฟอร์ม) แล้วส่ง HTML ที่สมบูรณ์กลับไป — และเมื่อกดปุ่ม
เซิร์ฟเวอร์จะรับค่าที่กรอกไปคำนวณก่อน render กลับมาใหม่

สรุป: ไฟล์ HTML เป็นเพียง **แม่แบบ** ส่วน Flask คือ **โปรแกรมที่ทำให้แม่แบบมีชีวิต**

## 2. ฟอร์มส่งข้อมูลไป Python อย่างไร

1. ใน template มี `<form method="post" action="/calculate">` และ input แต่ละตัวมี
   `name` เช่น `name="vcc"`, `name="r1"`
2. เมื่อกด **Calculate DC Bias** เบราว์เซอร์รวบรวมค่าจากช่องทั้งหมด สร้างเป็น
   **HTTP POST request** ไปที่ `/calculate` โดยส่งข้อมูลแบบ
   `application/x-www-form-urlencoded`
3. ฝั่งเซิร์ฟเวอร์ Flask จับคู่ URL `/calculate` กับฟังก์ชัน `calculate()` ใน `app.py`
4. ฟังก์ชันอ่านค่าด้วย `request.form.get("vcc")` ซึ่งได้ค่าเป็น **ข้อความ (string)**
   จึงต้องแปลงเป็นตัวเลขด้วย `float()` ก่อน
5. ค่าตัวต้านทานที่ผู้ใช้กรอกเป็น kΩ ถูกคูณ 1000 ให้เป็น Ω แล้วจึงเรียก
   `calculate_dc_bias(...)` ใน `dc_bias.py`
6. ผลลัพธ์ที่ได้ถูกส่งกลับเข้า template ผ่าน `render_template(...)` แล้ว Flask
   ส่ง HTML ที่ render เสร็จกลับไปให้เบราว์เซอร์เป็น **HTTP response**

จุดสำคัญคือ ตัวเลขที่เห็นบนหน้าจอ **ไม่เคยถูกเขียนไว้ในไฟล์ HTML** — มันเดินทาง
กลับมาเป็น response ใหม่ทุกครั้งที่กดปุ่ม

## 3. แก้สมการใน `dc_bias.py` แล้วต้องแก้ HTML หรือไม่

**ไม่ต้อง** ตราบใดที่ยังคืนค่าเป็น `BiasResult` ที่มี field ชื่อเดิม
เช่น ถ้าเปลี่ยนวิธีคำนวณ `VC` ให้ละเอียดขึ้น หรือเปลี่ยนค่าคงที่ β/VBE
ก็แก้แค่ใน `dc_bias.py` — หน้าเว็บยังแสดง `result.vc` ได้เหมือนเดิม

เหตุที่เป็นเช่นนี้เพราะแยกความรับผิดชอบชัดเจน

- `dc_bias.py` รู้แค่ **สมการและตัวเลข** ไม่รู้จัก HTML, HTTP หรือหน่วย kΩ
- `templates/index.html` รู้แค่ **วิธีแสดงผล** ไม่มีสมการฟิสิกส์อยู่ในนั้น

อย่างไรก็ตาม ถ้า **เปลี่ยนโครงสร้างข้อมูล** เช่นเพิ่ม field ใหม่ `vcb`
หรือเปลี่ยนชื่อ `vce` เป็น `v_ce` จะต้องแก้ทั้ง `app.py` และ template ด้วย
เพราะสัญญาระหว่างชั้น (interface) เปลี่ยน — นี่คือเหตุผลที่การแยกไฟล์ช่วยให้
การแก้สมการธรรมดาไม่กระทบหน้าจอ แต่การเปลี่ยน interface ต้องแก้ทั้งสองฝั่งอย่างตั้งใจ

## 4. ทำไมผลใน Region ที่แบบจำลองใช้ไม่ได้จึงต้องมี Warning

เพราะแบบจำลองที่ใช้ใน Lab นี้คือ **Forward-Active Approximation** ซึ่งตั้งอยู่บน
สมมติฐานว่า

- รอยต่อ base-emitter ไบแอสตรงและมีแรงดันคงที่ VBE ≈ 0.7 V
- กระแส collector เป็น β เท่าของกระแส base (β คงที่)
- รอยต่อ base-collector ไบแอสย้อน

เมื่อจุดทำงานออกนอกย่านนี้ สมมติฐานข้างต้น **ใช้ไม่ได้ทั้งหมด**

- **Cutoff** (`VTH ≤ VBE`): ทรานซิสเตอร์ไม่นำกระแส สมการ `IB = (VTH−VBE)/...`
  ให้ค่าติดลบซึ่งไม่มีความหมายทางกายภาพ
- **Saturation** (`VCE ≤ 0.3 V`): กระแส collector ถูกจำกัดด้วยวงจรภายนอก ไม่ใช่ β
  อีกต่อไป ค่า IC ที่คำนวณได้จึงสูงเกินจริงและเชื่อถือไม่ได้

ถ้าโปรแกรมแสดงตัวเลขออกมาเฉย ๆ โดยไม่เตือน ผู้ใช้อาจนำค่าที่ผิดไปใช้ในรายงาน
หรือการออกแบบต่อ Warning จึงทำหน้าที่เป็น **ขอบเขตความรับผิดชอบของแบบจำลอง**
บอกผู้ใช้ว่า "ตัวเลขนี้มาจากสมการที่ไม่ตรงกับสภาพจริงแล้ว"

หลักการเดียวกับที่ใช้ในงานวิศวกรรมจริง: เครื่องมือที่ดีไม่เพียงคำนวณได้
แต่ต้องบอกด้วยว่าผลของมันใช้ได้ภายใต้เงื่อนไขใด
